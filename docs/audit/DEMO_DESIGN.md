# 调查工作台设计范围

方向依据：TASK-014 的轻量、专业、复用现有 API 要求。

Operate 模式：让审阅者按 Incident → 计划/工具 → 假设/根因 → Evidence → 补丁/测试 → 审批的顺序完成一次审阅。桌面双栏，手机单栏；所有状态和产物来自认证 API，不预置成功数据。

浅色纸面、深青色正文、细分隔线、原生表单和折叠证据。系统字体用于操作界面；仅 Diff/ID/hash 使用等宽字体。不使用外部资源、框架、图像 comp 或装饰动画。该限定来自用户任务范围；不建立另一个营销品牌系统。

验收重点：数据及身份真实、模式清晰、审批绑定可见、错误可恢复、键盘可操作、桌面和移动端无溢出。静态壳可公开，所有数据接口仍需认证；DOM 使用 textContent，CSP 限制同源静态资源。

机械检测运行一次，使用 regex 降级模式（缺少 HTML parser modules），不能当完整无障碍审计。独立 finish review 要求修正 SQLite UTC 时间显示并保存产品约束；修正结果见交付报告。
